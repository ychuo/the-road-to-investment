# 如何提交与复盘

## 1. 先保护隐私

不要在公开仓库、公开聊天或截图中提交：

- 身份证号、银行卡号、开户地址；
- 手机号、邮箱、家庭住址；
- 登录凭证、验证码、完整交易单号；
- 未经家人同意的财务信息；
- 能反推出具体身份的公司与薪资细节。

金额可以统一除以一个系数，或只提交比例。不要随机改动各项金额，否则计算关系会失真。

## 2. 生成个人副本

```bash
npm run homework:new -- 01
```

若对应文件已存在，脚本会拒绝覆盖。这样可以避免误删你的作业。

## 3. 先自检，再求反馈

```bash
npm run homework:check -- 01
```

看到通过，只表示结构完整。接着逐项按照作业中心的量规打分，并在文末记录：

```text
自评分数：
最没有把握的两处：
最想获得的反馈：
```

具体提问比“帮我看看”更容易获得高质量反馈。

## 4. 反馈者只指出问题，不替你做决定

推荐反馈范围：

- 事实和来源是否不足；
- 推理是否跳步；
- 目标与配置是否矛盾；
- 规则是否可执行；
- 是否遗漏坏情景；
- 是否违反安全边界。

不推荐反馈范围：

- 直接给出“标准资产比例”；
- 推荐具体证券；
- 预测短期市场；
- 用自己的风险偏好替代作业者；
- 只根据近期收益评价组合。

## 5. 保留版本变化

每次修订在文末增加：

| 版本 | 日期 | 收到的反馈 | 采纳 / 不采纳 | 理由 |
| --- | --- | --- | --- | --- |
| v0.1 |  |  |  |  |

不采纳反馈完全可以，但必须说明理由。学习成果不在“听话”，而在能够解释决策。

## 6. 关于 Git

如果你熟悉 Git，可以在每份作业完成或修订后提交一次，以保留成长轨迹。请先确认仓库是否私有，并检查没有敏感信息。

一个清晰的提交节奏：

```text
docs(homework): complete starting-point report
docs(homework): revise emergency-fund assumptions
docs(homework): add peer feedback to product analysis
```

如果不熟悉 Git，也可以在文件名中使用日期和版本号。

## 7. 作业通过后

不要把通过作业等同于“立刻实盘”。课程推荐顺序：

1. 通过结构自检；
2. 按量规达到 80 分或完成一次修订；
3. 完成外部反馈；
4. 纸面模拟至少四周；
5. 等待 24～48 小时再读最终规则；
6. 若安全边界仍满足，再考虑小额、渐进执行；
7. 设置明确的下次复盘日期。

> 学习的目的不是让交易更快发生，而是让不合适的交易更少发生。
